## v1 Requirements (All Complete)

### Authentication

- [x] **AUTH-01**: User can create an account with email and password — Phase 1, Plan 01-03
- [x] **AUTH-02**: User can log in and stay logged in across app restarts — Phase 1, Plans 01-01 / 01-04
- [x] **AUTH-03**: User can log out from the app — Phase 1, Plan 01-06
- [x] **AUTH-04**: User can sign in via Google or Apple (social login) — Phase 1, Plan 01-05 (mock; real OAuth deferred)
- [x] **AUTH-05**: User can reset their password via an email link — Phase 1, Plan 01-04 (mock flow)

### Bike Discovery

- [x] **DISC-01**: User can see available e-bikes near them on a map — Phase 2, Plan 02-01
- [x] **DISC-02**: User can tap a bike to view its detail (battery %, price per minute, distance) — Phase 2, Plan 02-02
- [x] **DISC-03**: User can filter bikes by battery level, price range, or bike type — Phase 2, Plan 02-03
- [x] **DISC-04**: User can switch to a list view showing nearby available bikes — Phase 2, Plan 02-04

### Booking & Unlock

- [x] **BOOK-01**: User can reserve a specific e-bike — Phase 3, Plan 03-01
- [x] **BOOK-02**: User can unlock a bike by scanning its QR code via the app camera — Phase 3, Plan 03-02
- [x] **BOOK-03**: User can unlock a bike via Bluetooth proximity — Phase 3, Plan 03-03 (mock 3-state)
- [x] **BOOK-04**: User sees a booking confirmation screen with pickup instructions — Phase 3, Plan 03-01

### Active Ride

- [x] **RIDE-01**: User sees a live ride timer and running cost during an active session — Phase 4, Plan 04-02
- [x] **RIDE-02**: User sees the current battery percentage of the rented bike — Phase 4, Plan 04-02
- [x] **RIDE-03**: User sees their current location on a map during the ride — Phase 4, Plan 04-02
- [x] **RIDE-04**: User can end the ride with one tap and proceed to payment — Phase 4, Plan 04-02

### Payments

- [x] **PAY-01**: User is charged via their saved payment method when the ride ends — Phase 4, Plan 04-02 (mock processPayment)
- [x] **PAY-02**: User can add and manage payment methods — Phase 4, Plan 04-03 (view-only; Add stubbed per D-16)
- [x] **PAY-03**: User receives a ride receipt with cost breakdown after each ride — Phase 4, Plan 04-02
- [x] **PAY-04**: User can view ride history (list of past rides with date, duration, cost) — Phase 4, Plan 04-03

## v2 Requirements (Deferred — Not in Scope for v1.0)

- User can view and edit their profile (name, photo, language)
- User can manage notification preferences
- User can rate / review a bike after a ride
- User can see points or loyalty rewards
- Multi-language / localization support

---

## Out of Scope (v1.0)

- Fleet / operator management dashboard — separate product for bike operators
- Web version — mobile-first only
- Business / multi-rider accounts — personal tourist use only
- Profile management — deferred to v2; not critical for first-time tourist flow
