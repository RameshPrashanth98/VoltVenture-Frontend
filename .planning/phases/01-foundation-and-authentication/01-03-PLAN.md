<threat_model>
**Threats addressed in this plan:**

| Threat ID | Category | Component | Disposition | Mitigation |
|-----------|----------|-----------|-------------|------------|
| T-01-07 | Tampering | Double-submit on Create Account | mitigate | setIsLoading(true) called before await; button disabled={isLoading} immediately on first tap — prevents concurrent requests |
| T-01-08 | Information Disclosure | Password in form | mitigate | FormField secureTextEntry={true} on password field — obscures characters in UI |
| T-01-09 | Information Disclosure | Password logging | mitigate | handleSignUp must not log password value. Only log non-sensitive: email address (if needed), error codes |
| T-01-10 | Spoofing | Client-side validation bypass | accept | validateEmail/validatePassword are UX quality gates only. In Phase 1 the backend is mocked — real security validation happens server-side in future phases |
| T-01-11 | Information Disclosure | Token storage after signup | mitigate | authContext.signUp() uses SecureStore.setItemAsync (OS keychain) — not AsyncStorage. Verified in AuthContext created in 01-01 |

**Out of scope for this plan:** Social auth token security (Plan 01-05), login brute force (mock layer — real mitigation at backend), session fixation (auth token is generated fresh on each signUp mock call).
</threat_model>
