<objective>
Build the Log In and Forgot Password vertical slices. A returning user who opens the app sees the Login screen (has_registered=true, no token), enters credentials, reaches AppTabs. A user who restarts the app with a stored token never sees the Login screen — they boot directly to AppTabs. A user who forgets their password can request a reset and see a clear success state.

Purpose: Completes AUTH-02 (session persistence — the cold-start read side) and delivers AUTH-05 (password reset email request). These are the final email/password auth screens; Plans 01-05 and 01-06 complete the social auth and logout flows.

Output: LoginScreen and ForgotPasswordScreen replacing the Plan 01-01 placeholders.
</objective>

    2. Email FormField: label="Email", keyboardType="email-address", autoCapitalize="none". onBlur: validate with validateEmail; set emailError.
    3. Password FormField: label="Password", secureTextEntry={true}. onBlur: no format validation for login (mode='login' returns null from validatePassword). Error on this field is set server-side by WRONG_PASSWORD.
    4. "Forgot password?" link: TouchableOpacity aligned to the right, Label 14dp, DSColors.primary. onPress: navigation.navigate('ForgotPassword').

    5. finally: setIsLoading(false).

    All form inputs: editable={!isLoading}.

    Do not call navigation.navigate() after signIn — RootNavigator switches to AppTabs automatically on SIGN_IN dispatch.

    formError (top-level): if set, render a Text in Error color (DSColors.error) at label size (14dp) between the form and the Log In button. This handles the generic fallback error without an alert.

**Threats addressed in this plan:**

| Threat ID | Category | Component | Disposition | Mitigation |
|-----------|----------|-----------|-------------|------------|
| T-01-12 | Tampering | Double-submit on Log In | mitigate | setIsLoading(true) before await; button disabled={isLoading} immediately — prevents concurrent signIn calls |
| T-01-13 | Information Disclosure | Password field on Login | mitigate | secureTextEntry={true} on password FormField — characters obscured in UI |
| T-01-14 | Information Disclosure | Password reset email enumeration | accept | Mock sendPasswordResetEmail always succeeds — does not reveal whether email exists (security best practice: never confirm/deny account existence on reset). Real backend should mirror this behavior. |
| T-01-15 | Tampering | Session fixation | accept | In Phase 1, tokens are mock-generated ('mock-jwt-token-signin-' + Date.now()). Real session fixation mitigation (server issues new token on login) is a backend concern for integration phase. |
| T-01-16 | Information Disclosure | Auth bootstrap timing (cold start) | mitigate | RootNavigator returns null while isLoading=true — OS splash covers the gap. No auth-state screen is visible before bootstrap completes. |

**Out of scope for this plan:** Brute force rate limiting (backend concern), real JWT validation (backend), social auth tokens (Plan 01-05).
</threat_model>
