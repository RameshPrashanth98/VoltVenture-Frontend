<threat_model>
**Threats addressed in this plan:**

| Threat ID | Category | Component | Disposition | Mitigation |
|-----------|----------|-----------|-------------|------------|
| T-01-22 | Tampering | Double-tap Log Out confirm | mitigate | setIsLoggingOut(true) before await authContext.signOut(); Log Out button disabled={isLoggingOut} immediately — prevents concurrent signOut calls |
| T-01-23 | Tampering | has_registered deletion on logout | mitigate | authContext.signOut() deletes 'auth_token' only — verified in AuthContext created in 01-01. has_registered='true' persists in SecureStore. Onboarding is never shown again after registration. |
| T-01-24 | Elevation of Privilege | Accessing Account screen without auth | mitigate | AccountScreen is only rendered inside AppTabs, which is only rendered when userToken != null in RootNavigator. Auth guard is at navigator level — not screen level. |
| T-01-25 | Denial of Service | Logout failure leaves user stuck | accept | handleLogout catches error and logs only. Dialog stays open on failure. User can retry. Acceptable for Phase 1 (mock — signOut should not fail in practice). Real error recovery handled in integration phase. |

**Out of scope for this plan:** Profile data deletion (deferred to v2), token revocation on backend (integration phase), multiple session management.
</threat_model>
