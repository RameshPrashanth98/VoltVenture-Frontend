## Spacing Scale

React Native uses density-independent pixels (dp). All values are multiples of 4.

| Token | Value | NativeWind Class | Usage |
|-------|-------|-----------------|-------|
| xs | 4dp | p-1 / m-1 | Icon gaps, tight inline padding |
| sm | 8dp | p-2 / m-2 | Compact element spacing, icon-to-label gap |
| md | 16dp | p-4 / m-4 | Default element spacing, input field padding |
| lg | 24dp | p-6 / m-6 | Section padding, card internal spacing |
| xl | 32dp | p-8 / m-8 | Screen horizontal padding, layout gaps |
| 2xl | 48dp | p-12 / m-12 | Major section breaks, onboarding visual area |
| 3xl | 64dp | p-16 / m-16 | Splash/onboarding hero area spacing |

**Exceptions:**
- Touch targets (buttons, tab bar items): minimum 44dp height per iOS HIG / Android accessibility guidelines
- Safe area insets: handled by `react-native-safe-area-context` — not added to the scale above, applied via `SafeAreaView` or `useSafeAreaInsets()`
- Screen horizontal padding: 24dp (lg) applied consistently across all auth screens

**Source:** Standard 8-point scale adapted for React Native. TODO: verify against `foundation-spacing--spacing-ramp` story on DS site.

## Interaction Contracts

### Auth Loading State
- Trigger: user taps primary CTA (Sign Up, Log In, Continue)
- Button enters disabled state immediately on tap (no double-submit)
- Button label replaced with `ActivityIndicator` (size="small", color=Text On Primary)
- All form inputs disabled during in-flight request
- On success: navigate to next screen
- On error: re-enable button and inputs, display inline error

### Inline Field Validation
- Validation fires on field blur (not on keystroke) — source: CONTEXT.md specifics
- Error text appears below the offending `TextInput` using RNP `HelperText` type="error"
- Error text color: DS Error color
- Error text size: Label 14dp
- Example errors (per CONTEXT.md):
  - Email: "Please enter a valid email address"
  - Password (Sign Up): "Password must be at least 8 characters"
  - Password (Log In): "Incorrect password. Try again or reset your password."
  - Email already in use: "An account with this email already exists. Log in instead?"

### Keyboard Avoidance
- All auth forms wrapped in `KeyboardAvoidingView` with `behavior="padding"` on iOS, `behavior="height"` on Android
- `ScrollView` inside `KeyboardAvoidingView` to allow scrolling past keyboard on small screens
- `keyboardShouldPersistTaps="handled"` on `ScrollView`

### Splash → Onboarding Transition
- Splash screen shows for 2 seconds minimum (or until app init complete, whichever is longer)
- Transition: fade-out splash, fade-in onboarding slide 1
- Implementation: React Navigation stack with `animation: "fade"` for this specific transition

### Onboarding Slides
- 3 slides, horizontal swipe gesture to advance
- Each slide: full-screen, image/illustration (top 55%), headline (Heading 24dp), tagline (Body 16dp)
- Progress dots at bottom of illustration area — active dot uses Accent color, inactive dots use Border color
- "Skip" text link (Label 14dp, Text Secondary) top-right corner on slides 1 and 2 — hidden on slide 3
- Slide 3 shows "Get Started" primary button (instead of Skip); tapping advances to Auth Landing
- Auto-advance: none — purely gesture + button driven

### Auth Landing Screen
- Primary CTA: "Create Account" — large primary button (full-width, 52dp height)
- Secondary: "Already have an account? Log in" — ghost/link style below the primary button
- Layout: brand mark/logo (top-center), tagline, then CTAs at bottom of screen

### Logout Confirmation
- Trigger: Account tab → "Log Out" row tap
- Modal dialog (RNP `Dialog`) appears over the Account screen
- Dialog copy:
  - Title: "Log Out?"
  - Body: "You'll need to sign in again to access your account."
  - Confirm button: "Log Out" — Destructive color fill
  - Dismiss button: "Cancel" — Ghost style
- On confirm: clear SecureStorage session token, navigate to Log In screen (not onboarding) — source: D-15
- On dismiss: close dialog, return to Account screen

### Session Persistence
- Session token stored in SecureStorage on sign-in success
- No UX contract needed for persistence itself — handled silently at app launch
- Root navigator checks auth state on mount; if valid token exists, routes directly to AppTabs (skipping AuthStack and onboarding)
- Source: D-02, D-14

### Social Auth Buttons
- Google: `@react-native-google-signin/google-signin` — source: D-16
- Apple: `expo-apple-authentication` — source: D-16
- Apple button is only shown on iOS (platform-conditional render)
- Social buttons appear below a divider ("or continue with") below the email/password form
- Button style: outlined, full-width, icon left-aligned, label centered

### Map Tab (Phase 1 Placeholder)
- Screen shows centered placeholder message
- Empty state heading: "Bikes Coming Soon"
- Empty state body: "The map will show available e-bikes near you. Coming in the next update."
- No interactive elements in Phase 1 placeholder
