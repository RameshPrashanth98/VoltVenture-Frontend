## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Camera → onBarcodeScanned | QR code data (result.data) crosses from camera hardware into JS — intentionally not validated per D-08 |
| OS → useCameraPermissions | Camera permission status read from OS permission store |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-04 | Tampering | QR code data (result.data) | accept | D-08 explicitly defers QR content validation to backend integration phase; any QR = success is the documented behavior |
| T-03-05 | Denial of Service | Multiple onBarcodeScanned firings per frame | mitigate | hasScanned useRef guard prevents repeated navigation.navigate calls; set to true on first successful scan |
| T-03-06 | Elevation of Privilege | Camera permission not checked before rendering CameraView | mitigate | Three-branch permission gate (null → loading, !granted+!canAskAgain → settings, !granted → request) before rendering CameraView |
| T-03-SC | Tampering | npm install expo-camera | accept | expo-camera is official first-party Expo package (github.com/expo/expo); verified via Package Legitimacy Audit in RESEARCH.md; not a slopcheck candidate |
</threat_model>
